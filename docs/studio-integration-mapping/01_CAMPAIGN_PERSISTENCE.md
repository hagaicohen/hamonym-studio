### Schema evidence limit
The inspected migration trees start with migration 003; no base CREATE TABLE for `campaigns` was found in those migration SQL files. The JSONB additions in migrations 033/036 belong to **partners/campaign_partners**, not campaigns, and cannot prove the campaign layout type. Before implementing SQL JSON-path updates, obtain a read-only `information_schema.columns` snapshot for campaigns and related tables, and the applied-migration record. No such query was run here.

## Data-loss and consistency hazards

1. **Whole-object replacement:** `buildUpdateQuery` assigns supplied JSON values; it does not merge nested layout keys. Preserve unknown members and send an intentional field delta. F currently has no `campaign-save-patch.ts`; the previously prepared adapter in another worktree must not be assumed integrated.
2. **Ambassador synchronization:** omission skips sync; a submitted non-empty list deletes absent slugs and upserts remaining records; an empty list returns early. Thus empty-list deletion semantics differ from options. Use the dedicated ambassador API for explicit management. [B/src/modules/campaigns/campaigns.service.js:516](C:/DEV/HamonymStudio/hamonym-backend/src/modules/campaigns/campaigns.service.js#L516)
3. **Registration replacement:** omission skips sync; a supplied array causes DELETE-all/reinsert, even if unchanged. Participant FK is ON DELETE SET NULL; snapshot text remains. B preserves `client_uid` only if migration 088 is present. Do not send options during a design save. [B/src/modules/campaigns/campaigns.service.js:595](C:/DEV/HamonymStudio/hamonym-backend/src/modules/campaigns/campaigns.service.js#L595); [B/migrations/026_registration_options.sql:34](C:/DEV/HamonymStudio/hamonym-backend/migrations/026_registration_options.sql#L34)
4. **No campaign-save transaction spanning all writes:** the campaign update and related synchronizations use the pool separately. Payment finalization has its own transaction and must not be confused with campaign saving.
5. **No revision/CAS protection:** UPDATE uses campaign ID, not an expected revision/updated_at condition. `updated_at` is metadata, not a concurrency check. Undo/Redo and `savedFingerprint` are client-side only. [F/src/app/modules/campaigns/services/campaign-studio-state.service.ts:1479](C:/DEV/HamonymStudio/hamonym-app/src/app/modules/campaigns/services/campaign-studio-state.service.ts#L1479); [F/src/app/modules/campaigns/studio/canvas/studio-history.ts:103](C:/DEV/HamonymStudio/hamonym-app/src/app/modules/campaigns/studio/canvas/studio-history.ts#L103)
6. **Bilingual gaps across copies:** B accepts `content_i18n` on update, but its fixed create INSERT does not store it. Missing migration 088 makes B drop translations silently on update and omit option UIDs. L does not implement these bilingual backend branches at all. ## Versioned Studio document verdict
**Reuse the existing layout JSON container first, subject to column-type and round-trip verification.** A proposed namespace such as `layout.simpleStudio` avoids new DB migrations for every visual control. It is not implemented today. Draft/published separation, public projection, size/schema validation and atomic revision checks are still required backend behavior; an arbitrary JSON key alone supplies none of them. Detailed proposal: report 04.
